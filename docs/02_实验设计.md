# 02 · 实验设计

对比实验是这个项目最容易做砸的部分：不是跑不出数字，而是**跑出来的数字不可比**。
这一篇给一套"变量可控、结论可用"的实验矩阵，以及每张图表该怎么呈现。

---

## 1. 实验总矩阵

命名规则：`A` = LoveDA 主线，`B` = Vaihingen 小样本，`C` = 消融/工程，`D` = 泛化。

| 编号 | 实验 | 变量 | 目的 | 预计耗时（2060 6GB） |
|---|---|---|---|---|
| **E0** | 最小距离基线 | 传统方法 | 定量参照，证明"深度学习有必要" | 5 min |
| **A1** | U-Net + ResNet34 | 主基线 | 拿到可信的第一个 mIoU | 2.5~3.5 h |
| **A2** | U-Net + EfficientNet-B4 | 编码器 | 更强主干的收益 | 4~6 h |
| **A3** | U-Net++ + ResNet50 | 解码器 | 密集跳连是否值得 | 4~6 h |
| **A4** | DeepLabV3+ + ResNet50 | 结构 | 空洞卷积/ASPP 对照 | 3~4 h |
| **A5** | **SegFormer-B2** | 结构 | Transformer vs CNN | 3~4 h |
| **B1** | Vaihingen U-Net + eff-b4 | 数据 | 小样本 + 强增强 | 1.5~2 h |
| **B2** | Vaihingen SegFormer-B2 | 数据 | 小样本下 Transformer 是否更吃预训练 | 2~3 h |
| **C1** | 损失：CE / Dice / CE+Dice / Focal+Dice | 损失 | 小类 IoU 的差异 | 4×2 h |
| **C2** | 增强：无 / 基础 / 强增强（+RandomShadow） | 增强 | 增强的边际收益 | 3×2.5 h |
| **C3** | 输入尺寸：384 / 512 / 768 | 分辨率 | 上下文 vs 显存 | 3×2 h |
| **C4** | 类别权重：无 / freq^-0.5 / freq^-1 | 不平衡 | 小类过曝的临界点 | 3×2.5 h |
| **C5** | 后处理：无 / 中值 / 中值+碎斑 / +边界平滑 | 后处理 | **不训练就能涨点** | 10 min |
| **D1** | LoveDA 训练 → Vaihingen 测试 | 跨数据集 | 域偏移下的泛化 | 推理 10 min |
| **D2** | 城市 → 乡村（LoveDA 内部） | 域内子集 | 城乡差异的影响 | 推理 10 min |
| **D3** | 4 倍降采样（0.3 m → 1.2 m） | 分辨率鲁棒性 | 换成 S2 数据前必测 | 推理 10 min |

> 全跑一遍约 **60~70 GPU 小时**。时间紧就砍 A3/A4 和 C3/C4，保留 A1/A5、B1、C1、C5、D1。

## 2. 可比性的三条铁律

1. **数据划分只做一次，所有人共用。** 把 `train/val` 的清单文件存进仓库（`data/splits/loveda_v1.csv`），
   任何实验都读它。改划分 = 所有数字作废。
2. **只改一个变量。** 换 SegFormer 时，增强、损失、epoch、batch（等效）必须与 A1 一致。
   Transformer 需要更小 lr 是**模型特性**，不算违反——但要在表格里注明。
3. **等效 batch 一致。** `batch × grad_accum` 保持 8。改变等效 batch 会改变最优 lr，结论就混了。

**评估口径固定：** 滑窗 512/步长 256，Hann 拼接，后处理统一"中值 3×3 + 最小图斑 80 px"，
报告 `mIoU / mF1 / OA / 逐类 IoU / 逐类 F1`。**训练时的 val mIoU 用同一套滑窗**，别用整幅前向（会虚高）。

## 4. 每个实验怎么做（操作要点）

### E0 传统基线

```bat
python scripts\run_baseline.py --data data\loveda --gsd 0.3
```

最小距离分类器（`src/rsc/baseline.py`）在真实数据上通常 0.35~0.45 mIoU，建筑 IoU 明显低
（灰屋顶 ≈ 道路的光谱）。这正好是"讲深度学习必要性"的最强论据：**建筑 IoU 从 0.3 到 0.7**。

### A1 U-Net 主基线（第一个要跑通的）

```bat
python scripts\train.py --config configs\loveda_unet_r34.yaml --data data\loveda
```

看什么：
- 前 2 个 epoch loss 应快速降到 1.5 以下；**不降 = 标签映射错了或归一化错了**（最常见的是漏了 remap）；
- 第 10 epoch 的 mIoU 应 > 0.35；40 epoch 收敛到 0.5+；
- 曲线抖动大 → lr 降到 3e-4；一直在 0.3 徘徊 → 检查类别权重是否过强。

### A5 SegFormer（和 A1 成对出现才有意义）

```bat
python scripts\train.py --config configs\loveda_segformer_b2.yaml --data data\loveda
```

- SegFormer 的 lr 要小一个量级（6e-5），warmup 拉长到 2 epoch，weight_decay 0.01；
- 常见误区：拿 U-Net 的 lr 直接训 SegFormer → 前 3 个 epoch loss 就发散，然后误判"Transformer 不适合遥感"。

### C5 后处理（性价比最高，10 分钟涨 1~3 个点）

```bat
python scripts\run_baseline.py --min-size 80      :: 对比 --min-size 0
```
真实数据上：中值滤波 + 最小图斑 80 px 通常能让 mIoU +0.5~1.5、**建筑 F1 +2~4**（碎斑被吃掉）。
把"后处理前/后"的对比图放进报告，是很讨喜的一页。

### D3 分辨率鲁棒性（决定能不能接 Sentinel-2）

把验证集影像 4 倍降采样（`cv2.resize(..., interpolation=cv2.INTER_AREA)`）再推理，
模拟 0.3 m → 1.2 m。若 mIoU 掉超过 15 个点，说明模型过度依赖纹理，接 S2（10 m）之前必须做
**多尺度训练**（`data.py` 里的 `RandomScale` 已经在做）。

## 5. 统计显著性：别用单次结果下结论

深度学习单次结果有 **±1~2 个点**的随机波动。表格里至少给 **3 个 seed 的 mean ± std**：

```bat
for %%s in (42 43 44) do python scripts\train.py --config configs\loveda_unet_r34.yaml ^
    --data data\loveda --out runs\a1_seed%%s
```

- 两个模型的差距 < 1 个点且 std 有重叠 → **不要写"优于"**，写"相当"；
- 想写"显著提升"，最好做配对 t 检验或报告 3 seed 的区间。

## 6. 误差分析（决定报告质量的一节）

必出三张图：

1. **混淆矩阵**（`outputs/demo_confusion.png` 的样式）：找出主要混淆方向。
   遥感 6 类的经典混淆对：`建筑 ↔ 道路`（灰色屋顶 vs 沥青）、`裸土 ↔ 建筑`（浅色屋顶 vs 裸地）、
   `阴影 ↔ 水体`（暗像素）。
2. **三联对比图**（`comparison_figure`）：一张全景 + 两处局部放大，**好例和坏例都要放**。
   只放好例的图一眼假。
3. **逐类 IoU 条形图** + 面积占比：说明"小类拉低 mIoU"的成因。

一句话结论模板：
> "模型主要误差来自建筑与不透水面的混淆（占错分像素的 41%），其次是阴影区的水体误判（23%）；
> 引入 DSM 高程或后处理规则（建筑紧致度 > 0.7 判为建筑）可缓解。"

## 8. 常见分析陷阱

| 陷阱 | 现象 | 正确做法 |
|---|---|---|
| 验证集虚高 | val mIoU 比 test 高 5 个点 | 划分按区域，不要随机打散瓦片 |
| 整幅前向评估 | val 一次跑完，mIoU 比滑窗高 | 统一滑窗口径 |
| 只看 mIoU | mIoU 0.65 但建筑 IoU 只有 0.4 | 必须报逐类指标；业务上建筑才是重点 |
| 忽略类别不平衡 | 植被 60%，全预测植被也能 OA 0.6 | 报 mIoU/mF1，别只报 OA |
| 后处理调参泄漏 | 在 test 上调 min_size | 后处理参数只在 val 上定 |
| 用 test 挑模型 | 反复看 test 结果选 epoch | test 只看一次 |
