# 01 · 数据与标注

数据决定了这个项目的上限。这一篇解决四件事：**用哪个数据集、怎么下、怎么对齐标签、怎么抽样验证点**。

---

## 1. 三个数据集怎么选

| 维度 | LoveDA | ISPRS Vaihingen | SpaceNet（AOI 2/4 等） |
|---|---|---|---|
| 分辨率 | 0.3 m（Google Earth） | 0.09 m（航空 ADS80） | 0.3~0.5 m（WorldView-2/3） |
| 规模 | 5,987 幅 1024×1024（2,713 城市 + 3,274 乡村） | 33 幅（2494×2064 等，16 幅全标注） | 每 AOI 数千 km²，>1.1 亿栋建筑足迹 |
| 类别 | 7 类（含 barren/forest/agriculture） | 6 类（不透水面/建筑/低植被/树/车/杂） | 二类（建筑/背景）+ 道路（SpaceNet 7） |
| 波段 | RGB | 近红外-红-绿 + DSM/nDSM | 8 波段多光谱 + 全色 |
| 标注质量 | 众包+人工，城乡都有，**含 166,768 个对象** | 人工精细，**建筑边界最权威** | 从 OpenStreetMap 转换，**有系统性偏移** |
| 获取 | Zenodo 直接下（约 3.5 GB） | 需填申请表（学术用途） | AWS 公开桶，`--no-sign-request` 免账号 |
| 难度 | 中（城乡域差异大） | 高（小样本 + 阴影 + 类别极不平衡） | 中（二类任务，影像-标注有偏移） |
| 适合 | **主力训练集 + 泛化测试** | **小样本/边界精度对比** | **建筑提取专项 + 大区域制图** |

**推荐组合（也是本仓库配置文件的顺序）：**

1. **LoveDA 打底**——类别和我们 6 类几乎一一对应，量大、城乡都有，先把 U-Net 训到 mIoU 0.70 左右；
2. **Vaihingen 做"精度天花板"对照**——数据量小，模型上限明显，适合讲"小样本 + 强增强 + 预训练"；
3. **SpaceNet 只做建筑专项**——验证"建筑提取"这条业务线，顺手可以给解译图提供真实底图。

> ⚠️ 三个数据集的**许可都是"学术/非商业"或"需遵守原始条款"**。论文里要写清数据来源和许可；
> 商用必须重新确认（LoveDA 见 GitHub LICENSE，ISPRS 需申请时勾选用途，SpaceNet 见 AWS 注册表条款）。

## 2. 下载与整理

### 2.1 LoveDA（推荐第一站）

- 官方仓库：<https://github.com/Junjue-Wang/LoveDA>
- 数据下载：Zenodo 记录 `5706578` → <https://zenodo.org/records/5706578>
  （`Train.zip` / `Val.zip` / `Test.zip`，Train 约 2.2 GB）

解压后目录：

```
LoveDA/
  Train/Urban/images_png/*.png   masks_png/*.png
  Train/Rural/...
  Val/Urban|Rural/...
  Test/...            ← 无标签，用于榜单
```

**标签值是 0~6**，不是 0~5：

| LoveDA 值 | 含义 | 本项目 |
|---|---|---|
| 0 | background（未标注/其他） | **255 忽略** |
| 1 | building | 1 建筑 |
| 2 | road | 2 道路 |
| 3 | water | 3 水体 |
| 4 | barren | **5 裸土** |
| 5 | forest | **4 植被** |
| 6 | agriculture | **4 植被** |

```bat
python scripts\prepare_loveda.py --src D:\data\LoveDA --dst data\loveda
```

脚本会做三件事：改名（`urban_` / `rural_` 前缀防止重名）、**把标签重映射到 0~5 + 255**、打印类别像素占比。

> 坑 1：官方 `masks_png` 是**三通道灰度图**，直接 `cv2.imread` 会读成 3 通道，记得取 `[..., 0]`。
> 坑 2：`Test` 没有标签，别拿它算 mIoU；本仓库默认 `--skip-test`。
> 坑 3：LoveDA 的 `background` 既包括"未标注区"也包括"确实不属于 6 类的地物"，**一律当 255 忽略**，别当第 7 类去训。

### 2.2 ISPRS Vaihingen

- 介绍页：<https://www2.isprs.org/commissions/comm2/wg4/benchmark/2d-sem-label-vaihingen/>
- 申请入口：页面上的 *data request form*（填单位/用途，通常 1~3 天邮件回复）

需要下两个包：`ISPRS_semantic_labeling_Vaihingen.zip`（影像 + DSM）与 `..._ground_truth_eroded_COMPLETE.zip`（腐蚀后的完整标注）。

**标签值 0~5**：

| Vaihingen 值 | 含义 | 本项目 |
|---|---|---|
| 0 | impervious surface（不透水面：路面/广场/停车场） | **2 道路** |
| 1 | building | 1 建筑 |
| 2 | low vegetation | 4 植被 |
| 3 | tree | 4 植被 |
| 4 | car | **255 忽略**（面积太小，单独成类会拉低 mIoU） |
| 5 | clutter/background | 255 忽略 |

> 坑 1：影像是 **NIR-R-G**，直接当 RGB 训会得到"绿色天空"。要么调序成 R-G-NIR 当伪彩，
> 要么把 `in_channels` 设 4 用 NIR（`configs/vaihingen_unet_effb4.yaml` 里留了开关）。
> 坑 2：只有 16 幅是"全标注"，其余用 eroded 版本（边界被腐蚀掉一圈）——**损失函数必须支持 ignore=255**，
> 否则模型在边界上学到的是错的。
> 坑 3：9 cm 分辨率意味着 512×512 只有 46 m×46 m，一栋大楼就占满整块。裁 512 时**步长设 256**，否则样本多样性不够。

### 2.3 SpaceNet

- 数据集总览：<https://spacenet.ai/datasets/>
- AWS 公开数据集注册表：<https://registry.opendata.aws/spacenet/>（桶：`s3://spacenet-dataset/`）

```bat
:: 免账号下载（AWS CLI v2，注意 --no-sign-request）
aws s3 ls s3://spacenet-dataset/ --no-sign-request
aws s3 cp s3://spacenet-dataset/AOI_2_Vegas/ D:\data\spacenet\AOI_2_Vegas --recursive --no-sign-request --quiet
```

结构：`RGB-PanSharpen/`（8bit 三波段，最省事）、`PS-RGB/`、`MUL/`（8 波段 16bit）、
`geojson/buildings/`（建筑足迹，WGS84）。

**把 footprint 变成标签栅格**（关键一步，官方不给 mask）：

```python
# scripts/ 下没有现成脚本，因为 AOI 坐标系各不相同；思路：
import geopandas as gpd, rasterio
from rasterio import features
gdf = gpd.read_file("geojson/buildings/AOI_2_Vegas_geojson_buildings.geojson")
with rasterio.open("RGB-PanSharpen/AOI_2_Vegas_img1.tif") as src:
    gdf = gdf.to_crs(src.crs)
    mask = features.rasterize(((g, 1) for g in gdf.geometry),
                              out_shape=(src.height, src.width),
                              transform=src.transform, fill=0, dtype="uint8")
```

> 坑 1：SpaceNet 的 footprint 来自 OSM，**与影像有 1~3 像素的系统性偏移**（不同城市还不一样）。
> 直接训会得到一个"永远偏向某方向偏移"的模型。建议：先做互相关配准（`cv2.phaseCorrelate`）或用大 crop 容忍。
> 坑 2：建筑标注是"屋顶轮廓"，高层建筑的投影和屋顶不重合，市中心区域误差大。
> 坑 3：`MUL` 是 16bit，直接 `imread` 再 /255 会全黑，必须百分位拉伸（本仓库 `infer.predict_geotiff` 已处理）。

## 3. 裁剪（把大图变成训练样本）

```bat
python scripts\cut_geotiff.py ^
    --src data\raw\vaihingen_area15.tif ^
    --label data\raw\vaihingen_area15_label.tif ^
    --out data\vaihingen\train --size 512 --stride 256 --preset vaihingen ^
    --min-valid 0.3
```

参数怎么定：

| 参数 | 建议 | 原因 |
|---|---|---|
| `--size` | 512（0.3~0.5 m）；9 cm 数据用 512 也可 | 6 GB 显存下 512/bs4 是甜点；太小丢失上下文，太大 batch 掉到 1 |
| `--stride` | 训练 256（50% 重叠），验证 256 | 重叠保证建筑不被切一半；验证时重叠+滑窗拼接更准 |
| `--min-valid` | 0.3 | 丢掉"90% 是忽略区"的块，避免 loss 被无效像素稀释 |
| `--preset` | 对应数据集 | 标签映射走 `palette.LABEL_PRESETS` |

**数据检查清单**（S1 阶段必做，20 分钟能省 3 天）：

- [ ] 随机抽 20 张瓦片，把 `image` 和 `mask` **叠加显示**，确认没有错位/翻转；
- [ ] 统计类别像素占比，最小类 < 0.5% 就要开类别权重或 `balance_sampler`；
- [ ] 确认 `255` 区域的占比（Vaihingen eroded 边界通常 5~10%）；
- [ ] 确认没有"全黑"瓦片（16bit 未拉伸的典型症状）；
- [ ] 训练集和验证集**按区域划分**，不要随机打散同一幅大图的瓦片（否则空间自相关会让 val mIoU 虚高 3~5 个点）。

## 4. 自建数据（结合你的 GEE 能力）

公开数据集不够"本地化"时，用 GEE 自建：

1. `gee/export_s2_patches.js` —— Sentinel-2 时相合成 + 按 512×512 网格导出 GeoTIFF 到 Drive；
2. 下载后 `python scripts\cut_geotiff.py --src xxx.tif --out data\mine\train --size 512`（无 `--label` 时只切影像）；
3. 标注：**Labelme / CVAT**（小图）或 **QGIS + 多边形**（大图）。6 类建议每类 ≥ 200 个独立图斑；
4. 标注规范（写进标注手册，比什么都重要）：
   - 建筑：以**屋顶外轮廓**为准，含裙楼，不含雨棚/围墙；
   - 道路：机动车道 + 人行道 + 硬化广场（与 ISPRS 的 "impervious" 对齐）；
   - 水体：常水位线以内，不含滩涂；
   - 植被：树冠 + 草地 + 农田（农田单列时另设子类）；
   - 裸土：无植被覆盖的土表、在建工地、堆场；
   - 边界像素：**宽度 2 px 的忽略带**（`255`），比强行二选一更稳。

> GEE 的价值不只是"拿影像"：它还能**在线推理**——把 `ee.Image` 切块 `sampleRegions` 后
> 走 `ee.Model.fromVertexAI` 或导出到本地推理。详见 `docs/03`。

## 5. 样点数据（精度评价与野外核查）

这是遥感项目和纯 CV 项目最大的差别：**验收看的是样点，不是 mIoU 榜。**

### 5.1 布设原则

| 要素 | 做法 | 说明 |
|---|---|---|
| 抽样方式 | **分层随机**（按类别分层） | 纯随机会被植被/农田淹没；Olofsson et al. (2014) 的标准做法 |
| 每类数量 | ≥ 50，建议 60~100 | 50 个点才能把 OA 的 95% 置信区间压到 ±10% 以内 |
| 总数量 | 300~600 | 超过 1000 个点的核查成本会失控 |
| 最小间距 | 50~100 m | 避免空间自相关导致"同一块地抽 5 个点" |
| 边界处理 | 距类别边界 ≥ 5 px 的点剔除 | 边界本身就有 ±1 px 歧义，核查无意义 |
| 记录字段 | 见 5.3 | 必须能落到经纬度并回填 |

### 5.2 已生成的样例（可直接用）

`data/sample/sample_points.csv`，**720 个点**（3 张验证瓦片 × 6 类 × 40 点），字段：

val_000_00001,val_000,1001,863,0,background
val_000_00002,val_000,58,209,0,background

| 字段 | 类型 | 说明 |
|---|---|---|
| `point_id` | str | `城市_类别_序号`，唯一 |
| `lon` / `lat` | float | WGS84，直接从 GEE/ArcGIS 导出 |

### 5.4 精度怎么算（论文/报告要写清）

逐像元 mIoU 只能内部对比，**对外验收用面积加权总体精度**：

```
W_i  = 第 i 类面积 / 总面积              （分层权重）
p_i  = 第 i 类样点中判对的比例
OA   = Σ W_i · p_i
95%CI ≈ 1.96 · sqrt( Σ W_i² · p_i(1-p_i) / (n_i - 1) )
```

报告里应该给：`OA ± CI`、`用户精度(UA)`、`生产者精度(PA)`、每类样点数。只给一个 mIoU 是不专业的。
